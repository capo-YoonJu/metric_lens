# ADR-0009: 표준이 있으면 표준하고만 비교, 보류는 표준을 누적

## 상태
Accepted

## 맥락
ADR-0007에서 표준 포인터(`metric_standards`)를 도입했지만, `conflict_detect_node`는
여전히 같은 이름의 **모든** 과거 부서 정의와 매번 비교했다. 표준이 이미
`adopted_a`로 확정된 뒤에도, 이미 기각된(그리고 다시는 안 바뀔) 예전 부서
정의들과 계속 재비교하며 같은 충돌을 반복 생성했다.

또한 `metric_standards`는 `metric_name`이 PK라 표준을 하나만 가질 수 있었다.
`wontfix`(보류 — "부서별 정의 차이 허용")를 선택하면 포인터를 아예 지워버려서,
"둘 다 정당한 정의로 인정한다"는 의도와 달리 오히려 표준이 하나도 없는
상태가 됐다.

## 결정

1. **표준이 있으면 표준하고만 비교.** `metric_standards`에 해당 지표 이름의
   행이 하나라도 있으면, 새로 등록되는 지표는 그 표준 부서(들)의 정의와만
   비교한다. 과거에 이미 검토·기각된 부서 정의는 재비교하지 않는다. 아직
   표준이 없는 지표 이름은 기존처럼 모든 부서 정의와 비교(fallback).

2. **`metric_standards`가 지표당 여러 행을 가질 수 있도록 스키마 변경**
   (`PRIMARY KEY (metric_name, department)`). 기존 단일 PK 스키마의 DB는
   `init_db()`가 자동 마이그레이션한다.

3. **resolution별 표준 갱신 방식을 분리:**
   - `adopted_a` / `adopted_b` / `merged` — `replace_standards()`: 기존 표준을
     모두 지우고 승자 하나만 남김 (명시적으로 하나를 택했으므로 나머지는
     기각)
   - `wontfix` — `set_standard()`를 이번 충돌에 관련된 각 부서(신규 등록 부서
     + 비교 대상이 된 기존 부서들)에 대해 호출, **기존 표준을 지우지 않고
     추가**. "기존 표준 + 이번에 보류된 정의"가 함께 표준 집합이 됨

부서별 `MetricDefinition` 원본은 여전히 수정·삭제하지 않는다 (ADR-0007 원칙
유지) — `metric_standards`는 포인터 집합일 뿐이다.

## 결과
- 표준이 확정된 뒤에는 과거 기각된 정의와의 반복 재충돌이 사라짐 — HITL
  검토 큐가 실제로 새로 검토해야 할 것만 보여줌
- `wontfix`를 반복하면 표준 집합이 누적되어(예: 3개 부서가 각자 보류로
  인정받으면 표준 3개), 4번째 부서 등록 시 3개 모두와 비교됨 — 병렬로
  인정된 정의가 늘어날수록 비교 비용도 늘어남(허용 가능한 트레이드오프,
  대부분 지표는 부서 2~3개 수준)
- `adopted_a`/`adopted_b`/`merged`로 다시 결정하면 누적된 표준 집합을
  하나로 되돌릴 수 있음 (예: 여러 부서가 보류로 공존하다가 나중에 하나로
  통합 결정)
- 이름이 다른 지표 간 충돌(synonym/semantic_diff)은 이 스코핑 대상이
  아님 — ADR-0007과 동일하게 범위 밖
